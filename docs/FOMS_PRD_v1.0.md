# FOMS v1.0 — 产品需求文档（正式基线）

**产品名称：** Freight Operations Management System  
**版本：** v1.0  
**状态：** 已确认的第一期业务基线；技术细节由阶段 0 进一步细化  
**首期部门：** 业务部  
**统计时区：** Asia/Shanghai

## 1. 产品目标

建设供货代公司内部员工使用的运营问题管理与数据分析系统，将每日业务问题、异常和运营数据统一收集、处理、统计和沉淀。

系统需要形成完整闭环：员工提交 → 管理审核 → 责任分派 → 处理跟踪 → 结果确认 → 数据统计 → AI 辅助分析 → 管理报告。

## 2. 已确认业务决策

| 项目 | 决策 |
|---|---|
| 首期使用部门 | 业务部 |
| 数据提交方式 | 网页填写 + Excel 上传 |
| 普通员工数据范围 | 仅本人记录 |
| 部门报告权限 | 仅授权管理角色 |
| AI 方式 | 云端大模型 API，须经公司批准 |
| 报告类型 | 日报、周报、月报 |
| 数据来源 | 手动录入、Excel、现有系统导出 |
| Excel 导入 | 标准模板 + 非标准文件字段映射 |
| 部署方式 | 待公司环境评估，保持可迁移 |

## 3. 用户角色与权限

### 3.1 普通业务员工（business_employee）
- 登录系统。
- 创建问题、补充本人问题材料。
- 录入每日运营数据。
- 上传标准或非标准 Excel。
- 查看本人提交的问题、数据和导入记录。
- 查看本人问题处理进度。
- 不得查看其他员工记录、部门驾驶舱或部门报告。

### 3.2 部门负责人（department_manager）
- 查看授权部门全部问题和运营数据。
- 审核、分类、分派和跟踪问题。
- 确认解决结果。
- 查看部门看板。
- 生成、审核、发布和导出部门报告。

### 3.3 运营管理员（operations_admin）
- 管理业务类型、问题分类、业务环节和渠道字典。
- 管理 Excel 模板及字段映射规则。
- 审核导入结果、处理异常数据。
- 查看授权部门数据并协助问题管理和报告生成。

### 3.4 公司管理层（company_manager）
- 只读查看已发布的部门日报、周报、月报及管理看板。
- 导出已发布报告。
- 默认不能修改问题、原始运营数据或 AI 分析内容。

### 3.5 系统管理员（system_admin）
- 管理账号、角色、系统配置、密钥配置和基础设施。
- 不因系统管理员身份自动获得业务数据读取权限；需要额外业务授权。

权限必须在后端执行。前端隐藏按钮不构成安全控制。

## 4. 功能需求

### 4.1 登录与账号管理
- 管理员创建账号，不开放公开自助注册。
- 登录、退出、修改密码、启用/禁用账号。
- 密码安全哈希存储。
- 角色与部门授权。
- 登录日志和失败限制。

### 4.2 每日问题上报
问题字段至少包括：
- 唯一问题编号（建议格式 ISSUE-YYYYMMDD-XXXX）。
- 发生时间、上报时间、上报人、所属部门。
- 标题、描述、业务类型、业务环节、问题类别。
- 物流渠道、严重程度、影响范围、已采取措施。
- 可选内部业务关联编号及附件。

附件首期支持常见图片、PDF、Excel；具体类型和大小限制在技术设计中确定。

问题分类、业务类型、业务环节、渠道必须使用可维护字典，不得只写死在前端。

### 4.3 问题处理闭环
状态建议：
- 待审核
- 待补充
- 待分派
- 处理中
- 已解决
- 已关闭
- 已重新打开

需支持审核、分派、评论/处理记录、解决方案、人工确认根因、关闭和重新打开。状态变更必须记录操作者、时间、原状态、新状态及原因。AI 推测不能替代人工确认根因。

### 4.4 每日运营数据
问题事件和运营指标必须分开建模。首期指标包括：
- 出货票数（票）
- 出货件数（件）
- 货物重量（KG）
- 货物体积（CBM）
- 异常票数/异常件数（必须区分）
- 延误票数/延误件数（必须区分）
- 客户投诉数（次）
- 额外费用（金额及币种）

每条指标需记录日期、部门、业务类型、渠道、指标代码、数值、单位、来源、提交人及导入批次/原始行信息（如适用）。

比率必须使用同口径分子和分母。例如异常票率只能用异常票数除以出货票数；不得把异常件数除以出货票数并称为异常票率。缺少有效分母时不计算比率。

### 4.5 Excel 双模式导入

**标准模板模式**
- 系统提供带版本号的模板。
- 上传后自动识别模板版本和字段。
- 解析、校验、预览，用户确认后入库。
- 历史模板版本应继续可识别。

**非标准文件模式**
- 支持选择工作表、识别表头、推荐字段映射。
- 用户可调整映射并保存映射配置。
- 字段语义有歧义时必须人工确认。
- 自动推荐不等于自动授权入库。
- 预览、校验、重复检查后由用户确认导入。

校验至少覆盖文件类型/大小、工作表、必填字段、日期/数字格式、单位、渠道/业务字典和重复记录。显示成功、失败、待确认、疑似重复行数，并可下载错误行。

不得默认覆盖已有数据。每次导入保留批次、原文件、原始行、标准化行、导入人和时间。重复执行同一批次必须幂等。

### 4.6 个人工作台与管理驾驶舱
普通员工只查看个人问题数量、个人状态分布、本人数据及导入历史。

管理角色可查看部门总量、待审核、处理中、已解决、紧急问题、问题趋势、业务类型分布、渠道分布、处理时长、重复问题等，并支持日期、渠道、业务类型和严重程度筛选。

所有统计必须由后端基于真实数据库计算，不得用前端静态数据冒充。

### 4.7 AI 分析
AI 通过后端适配层调用经公司批准的云端模型。后端先计算统计数据，再进行必要脱敏，然后调用模型。

AI 功能：
- 问题分类和严重程度建议。
- 相似问题识别建议。
- 日报、周报、月报文字总结。
- 高频问题、渠道异常和潜在风险归纳。
- 可执行改进建议及待跟进事项。

AI 不得：
- 编造或自行填补统计数字。
- 将相关性直接描述为因果关系。
- 将推测当作已确认根因。
- 直接修改正式问题或指标数据。

需保存模型、提示词版本、生成时间、任务状态和结果。AI 结果须结构化校验并由授权人员审核后发布。AI 失败不得影响原始业务数据。

默认不得向外部模型发送客户姓名、联系方式、完整运单号、详细地址、客户商业机密或未经授权报价信息。

### 4.8 报告
支持日报、周报、月报，包含真实统计快照、重点问题、渠道情况、处理进度、趋势、风险和建议。

- 部门负责人/运营管理员：可生成、编辑、审核、发布。
- 公司管理层：只读查看已发布报告。
- 普通员工：不能查看部门报告。
- 报告支持历史版本及 Excel/PDF 导出。
- 发布后的历史报告保留生成时统计快照，不因后续数据变化而静默改变。

定时生成作为后续实施功能，生成时间、周期边界和时区需可配置。

## 5. 建议页面

员工端：登录、个人工作台、新增问题、我的问题、我的数据、Excel 上传、导入历史、个人设置。

管理端：管理驾驶舱、问题列表/审核/分派/处理、运营数据、导入管理、渠道及分类字典、AI 分析、日报/周报/月报、用户与系统设置、审计日志。

## 6. 非功能要求
- 多用户并发使用。
- 服务端持久化，PostgreSQL 为正式业务数据源。
- 后端强制执行权限和数据范围。
- HTTPS、安全密码哈希、密钥管理。
- 文件类型、大小和内容安全检查。
- 重要操作审计。
- 数据库和文件备份及恢复演练。
- 开发、测试、生产环境隔离。
- 数据库迁移可追踪。
- AI 调用超时、失败和重试有明确处理。
- 数据删除和覆盖必须受控并可审计。

## 7. 暂不纳入 v1.0
客户门户、订单/报价/财务全流程、船司/航司/快递商 API 自动对接、自动读取企业微信、自动报价、复杂跨部门审批。

## 8. 验收原则
- 员工可完成问题提交、个人记录查询、手动录入和两种 Excel 导入。
- 管理角色可审核、分派、处理和关闭问题。
- 员工无法越权读取他人记录或部门报告。
- 管理层只能读取已发布报告。
- 标准模板和非标准字段映射导入均有校验、预览和确认。
- 统计与数据库查询结果一致，口径明确。
- AI 报告基于真实统计快照且可人工审核。
- AI 故障不造成原始数据丢失。
- 备份可恢复，生产部署通过安全检查。

## 9. 阶段计划
0. 架构细化与需求检查。
1. 工程基础、数据库、登录和权限。
2. 问题上报与处理闭环。
3. 每日运营数据与 Excel 双模式导入。
4. 管理看板与统计分析。
5. AI 分析与报告。
6. 导出、部署、安全测试和上线验收。
