# FOMS v1.0 开发计划

## 全局约束
- 每阶段开始前阅读 PRD 和相关设计文档。
- 不擅自改变已确认权限与业务规则。
- 不删除/重建数据库，不未经确认覆盖数据。
- 数据库结构变更使用 Alembic。
- 真实业务数据存入 PostgreSQL。
- 不把 localStorage 当作正式业务数据存储。
- 不提交密钥或生产数据。
- 每阶段必须运行测试并提交验收报告。
- 未通过阶段验收不得进入下一阶段。

## 阶段 0：架构规划
交付：ER 图、数据字典、权限矩阵、API 清单、Excel 双模式导入设计、AI 脱敏设计、报告流程、部署方案、风险和待确认问题。
验收：确认员工 self 数据范围、管理层仅查看已发布报告、系统管理员不自动获得业务读取权、非标准 Excel 必须人工确认映射。

## 阶段 1：工程基础与登录权限
实现 React、FastAPI、PostgreSQL、SQLAlchemy、Alembic、Docker Compose、用户/部门/角色/权限、登录退出、后端 RBAC 和数据范围、审计基础。
验收：未登录不能访问 API；员工无法读取他人记录；管理角色按授权访问；系统管理员不自动读取业务数据；迁移和测试通过。

## 阶段 2：问题管理闭环
实现问题提交、字典、附件、个人问题列表、管理列表、审核、分派、状态流转、评论、解决记录和审计。
验收：编号唯一；权限正确；状态历史完整；附件访问受控；历史记录不能被无痕覆盖。

## 阶段 3：运营数据与 Excel
实现手动指标录入、标准模板下载/识别、非标准表格工作表选择、表头识别、字段映射建议、人工调整、映射配置复用、预览、校验、重复检查、错误行导出、确认入库和批次追踪。
验收覆盖空文件、多工作表、错误日期、缺字段、重复行、列顺序变化、字段别名、单位不匹配和批次重放。未经确认不得写入正式数据。

## 阶段 4：看板和统计
实现个人工作台与部门管理驾驶舱、筛选、趋势、渠道/业务/问题分类分布、处理效率和口径一致的比率。
验收：页面数字与数据库统计一致；员工只能看到个人统计；管理角色看到授权部门数据。

## 阶段 5：AI 分析和报告
实现 AI provider 适配层、密钥管理、脱敏、异步任务、分类建议、相似问题建议、日报/周报/月报、结构校验、人工审核、发布和版本管理。
验收：AI 不编造统计数，不修改原始业务数据；失败可重试；报告快照可追溯；管理层仅访问已发布报告。

## 阶段 6：导出、部署与上线
实现 Excel/PDF 导出、历史报告、定时任务、审计查询、备份恢复、HTTPS、生产配置、安全与并发测试、用户手册。
验收：越权、重复导入、数据丢失、密钥泄漏、备份恢复和导出权限测试通过。

## 每阶段 Codex 交付格式
1. 本阶段实现范围。
2. 修改/新增文件清单。
3. 数据库迁移说明。
4. 测试命令及实际结果。
5. 未解决问题和风险。
6. 人工验收步骤。
7. 建议 Git commit message。
