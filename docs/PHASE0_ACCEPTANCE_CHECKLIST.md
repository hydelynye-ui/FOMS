# FOMS 阶段 0 架构验收清单

Codex 完成阶段 0 后，由项目负责人逐项验收。所有阻塞项关闭前，不进入阶段 1。

## 需求与范围
- [ ] 文档与 FOMS_PRD_v1.0.md 的已确认决策一致。
- [ ] 首期只做业务部，模型支持未来多部门。
- [ ] 未擅自增加 v1.0 范围外模块。
- [ ] 未把待确认事项当作既定事实。

## 权限与安全
- [ ] 普通员工只能访问本人问题、指标记录和导入记录。
- [ ] 部门负责人/运营管理员按授权查看部门数据。
- [ ] 公司管理层只能只读访问已发布部门报告。
- [ ] 系统管理员不自动获得业务数据读取权限。
- [ ] 附件下载、导出、搜索和统计 API 具有同等权限检查。
- [ ] 设计包含 IDOR/越权负向测试。
- [ ] AI 脱敏、密钥管理和日志脱敏有明确方案。

## 数据库
- [ ] 核心表字段级定义完整。
- [ ] 主外键、唯一约束、索引和关系基数明确。
- [ ] 指标模型能区分票、件、KG、CBM、金额和币种。
- [ ] 指标唯一键可区分合法多次上报。
- [ ] 导入幂等、重复识别、更正和历史保留策略明确。
- [ ] 报告统计快照可复现。
- [ ] ER 图与数据字典一致。

## 问题流程
- [ ] 状态机、角色转换权限和异常路径明确。
- [ ] 状态历史、分派历史、评论和解决记录可追溯。
- [ ] 编辑和补充材料不会无痕覆盖历史。

## Excel 导入
- [ ] 标准模板版本管理明确。
- [ ] 非标准文件支持工作表和表头选择。
- [ ] 字段映射推荐与人工确认分离。
- [ ] 单位、日期、币种、枚举和缺失值规则明确。
- [ ] 预览、错误行、重复处理、批次幂等和更正流程明确。
- [ ] 文件安全与资源限制明确。

## AI 与报告
- [ ] AI 不直接访问数据库或修改正式业务数据。
- [ ] AI 统计事实来自后端，不允许编造。
- [ ] AI 输出经过结构验证和人工审核。
- [ ] 日/周/月周期、时区、版本和发布权限明确。
- [ ] 管理层仅能查看已发布报告。

## 部署与测试
- [ ] 本地、测试、生产环境边界明确。
- [ ] 内网和云部署选项及决策条件明确。
- [ ] 备份、恢复、日志、监控和健康检查明确。
- [ ] 权限、Excel、AI、报告、并发和恢复测试策略明确。

## 阶段门禁
- [ ] 所有阻塞性问题已解决或由项目负责人明确接受风险。
- [ ] 文档间命名与设计一致。
- [ ] Codex 提供 Git diff 和交付报告。
- [ ] 项目负责人明确批准进入阶段 1。
