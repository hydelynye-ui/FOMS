# FOMS v1.0

货代公司内部运营问题管理与数据分析系统（Freight Operations Management System）。

FOMS 面向国际物流货代公司的内部业务团队，用于统一收集每日业务问题与运营数据，支持问题审核和处理追踪、Excel 数据导入、运营统计、AI 辅助分析，以及日报、周报、月报生成。

> 当前仓库处于需求基线与工程初始化阶段，尚未包含可运行的业务系统代码。

## 项目目标

- 统一收集员工每日遇到的物流问题和业务异常。
- 统一管理手动录入及 Excel 导入的运营数据。
- 建立问题审核、责任分派、处理跟踪和关闭机制。
- 基于数据库真实数据生成统计看板。
- 使用经公司批准的云端大模型 API 辅助分类、归纳和报告撰写。
- 为管理人员提供经过审核发布的日报、周报和月报。

## v1.0 已确认范围

| 项目 | 决策 |
|---|---|
| 首期使用部门 | 业务部 |
| 数据提交方式 | 网页填写 + Excel 上传 |
| 普通员工数据范围 | 仅本人记录 |
| 部门报告权限 | 仅授权管理角色 |
| AI 方案 | 云端大模型 API |
| 报告类型 | 日报、周报、月报 |
| 数据来源 | 手动录入 + Excel + 现有系统导出 |
| Excel 导入 | 标准模板 + 非标准文件字段映射 |
| 部署方式 | 待公司环境评估，架构保持可迁移 |

## 角色

- 普通业务员工：提交问题和运营数据，只能查看本人记录。
- 部门负责人：查看部门数据，审核、分派和跟踪问题，审核发布部门报告。
- 运营管理员：维护业务字典、导入规则并协助运营管理。
- 公司管理层：只读查看已发布的部门报告。
- 系统管理员：管理账号、角色、系统配置和基础设施；业务数据读取权限需单独授权。

## 技术方向

- 前端：React、TypeScript、Vite、Tailwind CSS。
- 后端：Python、FastAPI、SQLAlchemy、Pydantic。
- 数据库：PostgreSQL。
- 数据迁移：Alembic。
- 文件存储：S3 兼容对象存储或 MinIO。
- 异步任务：Redis、Celery（按实施阶段引入）。
- 部署：Docker / Docker Compose。
- AI：通过后端适配层调用经批准的云端模型 API。

最终技术选型以 `docs/` 中经确认的设计文档为准。

## 开发原则

1. 先确认需求和架构，再按阶段实现。
2. 正式业务数据必须存储在服务端数据库，不以浏览器 localStorage 代替。
3. 权限必须由后端执行，不能只隐藏前端按钮。
4. Excel 导入必须经过解析、校验、预览和用户确认。
5. AI 只能分析后端提供的数据，不能编造统计数字或擅自认定问题根因。
6. AI 调用失败不得影响原始业务数据。
7. 数据库结构变更必须通过 Alembic 迁移。
8. 重要操作必须保留审计记录。
9. 不提交真实客户资料、运单信息、密码、API 密钥或生产环境配置。
10. 每个开发阶段都必须包含测试和验收记录。
